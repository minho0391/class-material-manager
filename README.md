# class-material-manager

수업에서 사용한 Google Docs 기반 수업자료를 수집하고, 과목별로 정리하며,
부족하거나 오래된 내용은 각 기술의 공식 문서를 기준으로 보충하는 개인 학습자료 관리 도구입니다.

기준 자료: `[Teacher's Module] 오르미 프론트엔드 개발 13기` (2026.4.7 ~ 8.21)

---

## 실행 방법

이 프로젝트는 **빌드 단계가 없습니다.** Node.js 24가 TypeScript를 그대로 실행할 수 있어
`.ts` 파일을 직접 돌립니다.

```bash
npm install         # 처음 한 번만

npm run refresh     # ★ 평소에는 이것 하나만 — 학습 데이터를 최신 상태로 갱신 (비교까지 포함)
cd viewer && npm install && npm run dev    # → http://localhost:3000

node src/index.ts help      # 명령 하나씩 따로 쓰고 싶을 때 (16개)
npm run typecheck           # 전체 타입 검사
npm test                    # 자동 시험 174건 — 서버도 인터넷도 필요 없습니다 (1초)
npm run e2e                 # 브라우저로 뷰어 확인 13건 — 뷰어는 알아서 띄웁니다
npm run security-check      # 남에게 보이기 전 민감정보 검사
npm run backup              # data/ 전체 백업 (refresh 전에도 자동으로 뜹니다)
npm run restore             # 백업에서 되돌리기
```

`npm run refresh` 가 아홉 단계를 올바른 순서로 부릅니다. 자세한 설명은 [12단계](#12단계-실행-결과)에.

```bash

node src/index.ts extract-zip --dry-run   # 결과만 보기
node src/index.ts extract-zip --only react
```

**다시 내려받지 않습니다.** 원본 zip 은 이미 `materials/<과목>/files/` 에 있으므로
그 파일만 읽습니다. 인증도 네트워크도 필요 없습니다.
앞으로 새로 받는 zip 은 `collect-files` 안에서 곧바로 내용까지 읽힙니다.

**압축을 풀지 않습니다** — 메모리에서만 읽고, zip 안의 코드는 절대 실행하지 않습니다.
`fflate` 를 고른 이유가 여기 있습니다. **압축을 풀기 전에 파일 목록과 원본 크기를 먼저 볼 수 있어서**,
"1KB 가 풀면 10GB 가 되는" 압축 폭탄을 풀기 전에 걸러낼 수 있습니다.

| 안전 제한 | 값 | 실제 자료에서 |
|---|---|---|
| 텍스트 파일 하나 | 128 KB | 1건만 걸림 (빌드 결과물 190KB) |
| zip 하나당 텍스트 총량 | 512 KB | 걸린 자료 없음 |
| zip 하나당 소스 개수 | 80개 | 걸린 자료 없음 |
| zip 하나당 엔트리 | 2,000개 | 최대 156개 |

제한에 걸린 파일은 작업을 실패시키지 않고 본문에 "생략됨"으로 남깁니다.

**한글 파일명 문제** — 윈도우 탐색기로 만든 옛 zip 은 파일 이름을 CP949 로 적으면서
"이건 UTF-8 이다"라는 표시를 켜지 않습니다. 그대로 읽으면 `소스이미지` 가 `¼Ò½ºÀÌ¹ÌÁö` 로 보입니다.
실제 수업자료에서 70건이 이랬습니다. 바이트를 되살려 UTF-8 → EUC-KR 순서로 다시 읽어 해결했습니다.

**본문에 싣지 않는 것**: `node_modules` · `dist` · `build` · `.next` · `__MACOSX` 안의 파일,
`package-lock.json` 같은 잠금 파일, `*.min.js` · 소스맵, 그리고 이미지·영상·폰트·실행파일.
다만 **파일 구조 목록에는 전부 남겨** 실습파일에 무엇이 들어 있는지 볼 수 있게 했습니다.

#### 무엇을 근거로 삼는가

과목이 다르면 **아예 견주지 않습니다.** 같은 과목이라는 사실만으로도 절대 잇지 않습니다.

1. **제목 낱말** — `jQuery_01_hover_button_1.pdf` ↔ `jQuery_01_hover_button_final_v202108.zip`
2. **본문·코드의 기술 낱말** — 설명자료가 다루는 기술을 실습 코드가 실제로 쓰는가
3. **소스 파일 이름** — `05. 유니언 타입` ↔ `05-union-type/union.ts`

#### 오탐을 막는 장치

낱말의 무게를 **자료에서 세어** 정합니다. 드물수록 무겁고, 흔하면 0 입니다.
이 계산이 없으면 같은 과목 자료가 서로 다 이어져 버립니다.

- **과목 안에서 흔한 낱말은 무게 0** — React 실습파일 대부분에 `useState` 가 있으므로
  React 자료끼리 견줄 때 그것은 아무것도 구별해 주지 못합니다.
  (이 장치를 넣기 전에는 `react`·`useState`·`onClick` 만 겹친 연결이 79건 나왔습니다)
- **과목 이름 자체는 근거가 아님** — react 자료끼리 "둘 다 react" 는 정보가 아닙니다.

### 12단계 실행 결과

명령 하나로 학습 데이터 전체를 최신 상태로 되돌립니다.

```bash
npm run refresh
```

#### 왜 필요한가

시간이 지나면 두 가지가 바뀝니다 — **강사님이 자료를 더하거나 고치고**, **공식 문서가 갱신됩니다.**
그때마다 여덟 개 명령을 순서대로 기억해 실행해야 했습니다. 순서를 틀리면 결과가 어긋납니다.

- 수집하고 분류를 안 하면 자료가 `_inbox` 에 남습니다
- 분류하고 연결을 다시 안 하면 `relations.json` 이 옛날 것을 가리킵니다
- 연결하고 학습자료를 안 만들면 화면이 옛날 코드를 보여줍니다

`refresh` 는 **기존 명령을 올바른 순서로 부르기만 합니다.** 일 자체는 원래 모듈이 그대로 합니다.

#### 실행 순서

```
[1/8] 기준 문서 링크 목록        ← 새 자료가 추가됐는지 여기서 발견
[2/8] Google 문서 수집          ← 본문 해시로 바뀐 것만
[3/8] 파일·폴더·게시형 문서 수집   ← md5Checksum 으로 바뀐 것만
[4/8] 과목 분류                 ← 옮길 것이 있을 때만
[5/8] 압축파일 내용 확인          ← 안을 못 읽은 zip 이 있을 때만
[6/8] 공식 문서 최신화           ← 다시 받아 바뀐 것만 저장
[7/8] 설명자료 ↔ 실습코드 연결 재계산
[8/8] 통합 학습자료 재생성
```

#### 무엇을 다시 하지 않는가 (증분 갱신)

전부 지우고 다시 만들지 않습니다. 기존 변경 감지를 그대로 씁니다.

| 대상 | 다시 하지 않는 근거 |
|---|---|
| Google 문서 | 본문 해시가 같으면 저장하지 않음 (3단계) |
| PDF·zip·이미지 | Drive 의 `md5Checksum` 이 같으면 내려받지 않음 (4단계) |
| zip 내용 추출 | 안을 이미 읽은 zip 은 건드리지 않음 (8단계) |
| 과목 분류 | 옮길 파일이 없으면 실행하지 않음 |
| **공식 문서 요약** | **내용 지문이 같으면 파일을 쓰지 않음 (12단계에서 새로 넣음)** |

#### 공식 문서 최신화

예전에는 `enrich` 를 돌릴 때마다 요약본 153개를 **내용이 같든 다르든 무조건 새로 썼습니다.**
그러면 "이번에 무엇이 바뀌었나"를 알 길이 없습니다.

이제 요약본 front matter 에 지문을 함께 적습니다.

```yaml
fetchedAt: 2026-08-22          # 이 내용을 공식 문서에서 받아온 날 (바뀔 때만 갱신)
contentHash: sha256:d85bc91…   # 공식 문서에서 뽑아낸 내용의 지문
```

다시 받아 지문이 같으면 **파일을 건드리지 않습니다.** 그래서 `fetchedAt` 이
"언제부터 이 문서가 안 바뀌었는지"를 뜻하게 됩니다.
결과는 `문서 바뀜 N · 새로 생김 N · 그대로 N` 으로 보고합니다.

> 지문은 **공식 문서에서 온 부분만** 씁니다. 수업자료 언급 횟수처럼 우리 쪽 사정으로
> 바뀌는 값은 넣지 않습니다. 그것까지 넣으면 공식 문서는 그대로인데 바뀐 것처럼 보입니다.

#### 실패했을 때

| 어디서 실패 | 어떻게 되는가 |
|---|---|
| 인증 | Drive 수집 두 단계를 건너뛰고, **로컬 단계는 그대로 진행**합니다 |
| 자료 한 건 | 기존대로 `data/failed.json` 에 기록하고 나머지를 계속합니다 |
| 공식 문서 한 건 | 이미 저장된 요약본을 그대로 두고 넘어갑니다 |
| 연결 재계산 | 학습자료 재생성을 **중단**합니다 (기존 학습자료는 그대로) |

어느 단계에서 무엇이 실패했는지 단계별 표로 보여주고, 마지막에
"기존 데이터는 그대로 남아 있습니다. 문제를 고친 뒤 다시 실행하면 이어서 갱신됩니다"라고 알립니다.

#### 다시 실행해도 안전한가

안전합니다. 연속 실행으로 확인했습니다.

| | 1회차 후 → 2회차 후 |
|---|---|
| `index.json` 항목 | 393 → 393 (추가·삭제 0) |
| 연결 | 62 → 62 (중복 0, **모든 점수·신뢰도 동일**) |
| 통합 학습자료 | 27 → 27 (중복 0, 코드 109 → 109) |
| 공식문서 요약 | 201 → 201 (새로 만든 것 0, **179건은 파일을 건드리지도 않음**) |
| zip 소스 | 837 → 837 |

> **다만 게시형 문서 1건은 매번 다시 저장됩니다.** `/d/e/…/pub` 주소는 요청할 때마다
> Google 이 조금씩 다른 HTML 을 돌려주어 내용 해시가 달라집니다. 그래서 전체 refresh 는
> "바뀐 것 없음" 대신 늘 "갱신을 마쳤습니다" 로 끝납니다.
> (`--skip-collect` 로 돌리면 "현재 데이터가 최신 상태입니다" 를 볼 수 있습니다)

#### dry-run

```bash
npm run refresh -- --dry-run
```

**파일을 하나도 바꾸지 않습니다.** 다만 네트워크를 쓰는 네 단계(링크 목록·문서 수집·파일 수집·공식 문서)는
미리보기가 없어 **건너뜁니다.** 나머지 네 단계는 실제로 미리 계산해 보여줍니다.
"dry-run 이라면서 일부는 바뀌는" 어정쩡한 동작을 만들지 않으려고 이렇게 정했습니다.

```bash
npm run refresh -- --skip-collect   # Drive 수집 건너뛰기 (로컬 자료만 다시 엮기)
npm run refresh -- --skip-enrich    # 공식 문서 확인 건너뛰기 (빠른 갱신)
```

#### 기존 명령은 그대로

`refresh` 는 편의 명령일 뿐입니다. 문제를 따져볼 때는 예전처럼 하나씩 실행하면 됩니다.

```bash
node src/index.ts collect / collect-files / classify / extract-zip / enrich / relate / build-learning
```

#### 첫 refresh 에서 드러난 것들

`enrich` 는 6단계 이후 처음 돌았습니다. 그 사이 8단계에서 **zip 소스코드가 수업자료 본문에 들어갔고**,
그래서 주제 매칭 결과가 달라졌습니다.

| | 전 | 후 | 까닭 |
|---|---:|---:|---|
| 공식문서 요약 | 153 | 201 | 매칭 대상이 늘어 48건이 새로 생김 (예전 17건은 남아 있음) |
| 학습자료의 공식문서 연결 | 81 | **82** | 아래 참고 |

연결 수는 중간에 한 번 58까지 떨어졌습니다. "이 주제를 다룬 수업자료" 를 고를 때
**먼저 만난 5건**만 담다 보니, zip 실습파일이 강사 설명자료를 밀어냈기 때문입니다.
설명자료를 앞세우도록 고쳐 82로 회복했습니다. ([`topic-matcher.ts`](src/enrich/topic-matcher.ts))

또 하나 — 서로 다른 공식 문서가 **같은 파일 이름**이 되는 경우가 있습니다.
`headers` 와 `Headers` 처럼 대소문자만 다른 짝이 그렇습니다. 윈도우·맥에서는 같은 파일이라
서로 덮어쓰며 **매번 "문서가 바뀌었다"고 잘못 세었습니다.** 이제 언급이 많은 쪽만 남기고
나머지는 건너뜁니다. (`이름 겹쳐 건너뜀 N` 으로 알립니다)

> **알려진 한계**
> - 주제에서 밀려난 **예전 요약본 17건이 폴더에 남습니다.** 지우지 않고 개수만 알립니다
>   (다음 실행에 다시 뽑힐 수 있어서, 지웠다 만들었다 하면 오히려 어지럽습니다)
> - 기준 문서에서 링크가 빠진 자료도 **지우지 않고 개수만 알립니다.** 잠깐의 오류로
>   사라진 것처럼 보일 수 있는데, 그걸 믿고 지우면 받아둔 자료를 잃습니다

> **현재 구현**: 학습 데이터를 최신 상태로 **다시 구성**합니다.
> **아직 구현하지 않음**: 수업 당시 내용과 최신 공식 문서 사이의 **의미 있는 차이 판정**
> (`deprecated` · `변경됨` · `현재 권장 방식`). 12단계는 그 판정을 할 수 있는 기반까지만 만듭니다.

### 13단계 실행 결과

12단계가 만든 기반 위에서 **"수업 때 배운 이 방식, 지금도 그대로 써도 되나"** 를 따집니다.

```bash
node src/index.ts compare             # data/comparisons.json 을 만듭니다
node src/index.ts compare --dry-run
node src/index.ts compare --only react
```

**비교 370건** — 그대로 사용 가능 296 · 확인 안 됨 49 · 버전 차이 24 · 사용 중단 1.

#### 지어내지 않습니다

판단의 근거는 **둘뿐**입니다. 둘 다 사람이 직접 확인할 수 있는 사실입니다.

| 근거 | 어디서 오는가 |
|---|---|
| 공식 문서가 밝힌 상태 | MDN 원문 front matter 의 `status: [deprecated]` |
| 수업 때 쓴 버전 | 실습 zip 안 `package.json` 의 의존성 (18개 파일, 패키지 23종) |

요약 글에서 "deprecated" 같은 낱말을 찾는 방식은 **쓰지 않습니다.**
그렇게 해봤더니 `justify-content` 문서의 "더 이상 사용할 수 있는 **공간**이 없다"가
사용 중단으로 잡혔습니다. 낱말은 근거가 되지 못합니다.

> 원래 6단계 요약은 첫 문단만 뽑아서 **deprecated 배너를 통째로 버렸습니다.**
> `<font>` 요약에 "글꼴 크기와 색을 정한다"만 남아 있었습니다.
> 이제 `enrich` 가 원문을 받은 자리에서 공식 상태를 붙잡아 요약본에 함께 적습니다.

#### 상태값

| | 뜻 |
|---|---|
| `CURRENT` | 공식 문서에서 확인되고, 문서가 아무 경고도 달지 않았습니다 |
| `DEPRECATED` | 공식 문서가 **이 기능을 쓰지 말라고** 직접 밝혔습니다 |
| `UNSTABLE` | 공식 문서가 실험적·비표준이라고 밝혔습니다 |
| `VERSION_GAP` | 수업 때 버전과 더 최신 자료(또는 이 저장소)의 버전이 **메이저**로 다릅니다 |
| `NOT_FOUND` | 우리가 가진 공식 문서 표본에 없어 **확인하지 못했습니다** — 없어졌다는 뜻이 아닙니다 |
| `REVIEW_REQUIRED` | 근거가 모자라거나 엇갈립니다. 사람이 봐야 합니다 |

#### 실제로 찾아낸 것

```
[DEPRECATED] html · <font>
  공식 문서가 이 기능을 더 이상 쓰지 말라고 밝혔습니다
  근거(공식 문서 상태): status: deprecated
      — "Do not use this element. Use the CSS Fonts properties to style text."
  근거(수업 설명자료): <font face="verdana" size="2"> Lorem ipsum dolor sit amet…
  가르친 곳: WSP_01_HTML_2020_v.pdf
  공식문서: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/font
```

버전 쪽에서는 수업자료 **안에서의 변화**가 드러납니다 — `react` `^18.2.0` → `^19.2.8`,
`vite` `^5.4.0` → `^8.2.0`, `react-router` `^7.18.2` → `^8.0.1`, `@vitejs/plugin-react` `^4.7.0` → `^6.0.4`.

#### 매칭 방식

- **문법·API** — 공식 문서 제목에서 코드에서 찾을 낱말을 뽑아 실습 코드와 **강사 설명자료 본문**에서 찾습니다.
  MDN 제목은 사람이 읽으라고 지은 것이라 그대로는 코드에 없습니다
  (`` `<font>` HTML font element `` → `<font` 태그로, `animation-name CSS property` → `animation-name` 으로).
  태그는 `<font` 로 찾습니다. 그냥 `font` 로 찾으면 CSS 의 `font-family` 가 전부 걸립니다.
- **패키지** — zip 안 `package.json` 의 의존성을 그대로 읽고, 같은 패키지를 쓰는
  다른 수업자료의 최신 버전 및 이 저장소의 버전과 메이저만 견줍니다.

npm 레지스트리에 묻지 않습니다. 확인할 수 없는 버전은 지어내지 않고 `null` 로 둡니다.

#### 근거 보존

모든 항목에 **왜 그렇게 판단했는지**가 함께 저장됩니다 —
관련 수업자료 위치 · 실습 코드 위치 · 공식문서 URL · 비교에 쓴 낱말 · 판단 이유 · 확인 시각.
화면에서도 그대로 보여 주니 직접 공식 문서로 가서 확인할 수 있습니다.

#### 화면에서 보기

- **`/compare`** — 상태별 필터(전체 · 사용 중단됨 · 버전 차이 · 확인 안 됨 · 그대로 사용 가능)
- **홈 카드** — "다시 볼 것 N건"
- **자료 상세 `/m/[docId]`** — 그 자료에서 다룬 기술 중 눈여겨볼 것이 있을 때만 영역이 나옵니다

#### refresh 와의 관계

`npm run refresh` 의 **9번째 단계**로 들어갔습니다. 다만 매번 전부 다시 견주지 않습니다.

```
[9/9] 수업 방식 ↔ 공식 문서 비교
→ 완료: 공식 문서가 그대로라 다시 견주지 않았습니다 (167건 확인)
```

비교할 때 본 공식 문서의 지문을 항목마다 저장해 두었다가, `enrich` 가 문서를 다시 받은 뒤
지문이 달라진 것만 **"다시 볼 것"** 으로 표시합니다. 바뀐 것이 있을 때만 전체를 다시 견줍니다.

> **알려진 한계**
> - `DEPRECATED` 를 찾을 수 있는 것은 **MDN 뿐**입니다. React·Next.js 문서에는 기계가 읽을
>   상태 칸이 없어, `<Deprecated>` 태그를 대놓고 쓴 경우만 인정합니다
> - 공식 문서 표본이 **과목당 40건**이라 `addEventListener`·`localStorage` 같은 것은
>   비교 자체가 불가능합니다 (`NOT_FOUND` 49건이 그것입니다)
> - "현재 버전"의 기준이 npm 최신이 아니라 **수업자료 안의 최신 + 이 저장소**입니다
> - 여전히 **"그 변화가 수업 방식을 낡게 만들었는가"** 는 판정하지 않습니다.
>   문장으로 설명하려면 AI 요약이 필요합니다

### 14단계 실행 결과

13단계는 **"어떻게 되었나"** 를 말했습니다. 14단계는 그 위에 **"그래서 내 코드를 고쳐야 하나"** 를 얹습니다.

`VERSION_GAP` 하나로는 답이 되지 않았습니다. 숫자가 달라도 코드는 그대로 돌아갈 수 있고,
숫자가 같아도 권장 방식이 바뀔 수 있기 때문입니다.

#### 변화의 종류와 무게

| 변화 종류 | 뜻 | 무게 |
|---|---|---|
| `NONE` | 달라진 것이 확인되지 않음 | NONE |
| `VERSION_ONLY` | 버전 숫자만 다름. 사용법이 달라졌다는 근거는 없음 | LOW |
| `RECOMMENDED_CHANGED` | 그대로도 돌아가지만 공식 문서가 다른 방식을 권함 | MEDIUM |
| `API_CHANGED` | 쓰는 방법 자체가 달라짐 | HIGH |
| `DEPRECATED` | 공식 문서가 쓰지 말라고 밝힘 | HIGH |
| `REMOVED` | 공식 문서가 없어졌다고 밝힘 | HIGH |
| `REVIEW_REQUIRED` | 근거가 모자라거나 엇갈림 | MEDIUM |

#### 근거의 순서

아무 문장이나 근거로 삼지 않습니다. 믿을 만한 순서가 정해져 있습니다.

```
1. 공식 문서 front matter 의 status:        ← 기계가 읽으라고 만든 칸
2. 공식 문서가 못박은 경고 상자 (WARNING)
3. 공식 대응표의 "예전 방식 → 현재 방식"      ← 주소가 반드시 붙어 있음
4. package.json 의 버전 숫자
```

여기 없는 것은 근거가 아닙니다. **버전 숫자만 보고 `API_CHANGED` 로 올리지 않습니다.**
대응표에 있는 것도 **코드에 그 방식이 실제로 들어 있을 때만** 잡습니다.
예전 방식과 현재 방식이 코드에 함께 있으면 옮기는 중일 수 있으므로 `REVIEW_REQUIRED` 로 넘깁니다.

#### NOT_FOUND 보완 — 49건 → 20건

13단계의 `NOT_FOUND` 는 "없어졌다"가 아니라 **"우리가 안 받아왔다"** 였습니다.
6단계가 과목당 상위 40건만 요약하는데 그 안에 들지 못한 것들입니다.

MDN 문서는 GitHub 저장소에 자리가 정해져 있습니다. 그래서 이름만 알면 짚어 볼 수 있습니다.

```
web/api/document/write/index.md
web/javascript/reference/global_objects/string/substr/index.md
web/css/reference/properties/clip/index.md
```

29건을 이렇게 찾아냈습니다. 검색 API 는 쓰지 않습니다 — 검색은 "비슷해 보이는 것"을 돌려주고,
그것을 믿으면 엉뚱한 문서가 근거가 됩니다. 못 찾으면 `NOT_FOUND` 그대로 둡니다.
남은 20건은 서드파티(swiper·fullPage.js·ScrollMagic)와 React·TypeScript 것이라 MDN 에 없는 게 맞습니다.

#### 실제로 찾아낸 것

| 기술 | 판정 | 공식 문서가 한 말 | 어디에 |
|---|---|---|---|
| `<font>` | DEPRECATED / HIGH | "Do not use this element. Use the CSS Fonts properties" | 강사 PDF |
| `document.write` | DEPRECATED / HIGH | "strongly discouraged. Avoid using it" | `javascript_final` 실습 3곳 |
| `clip` | DEPRECATED / HIGH | "encouraged to use the clip-path property instead" | 실습 zip 3개 |

버전 차이 24건은 모두 `VERSION_ONLY / LOW` 입니다. React 18 → 19 도 마찬가지입니다.
**수업 코드가 이미 `createRoot` 를 쓰고 클래스형 컴포넌트를 쓰지 않기 때문입니다.**
대응표에 `ReactDOM.render`·`Switch`·`useHistory`·`makeStyles` 를 넣어 두었지만 하나도 걸리지 않았습니다.
이것은 판정이 실패한 것이 아니라 **수업자료가 이미 최신이라는 사실**입니다.

#### 14단계에서 잡은 오탐 셋

**1. 남의 라이브러리 코드를 수업에서 배운 방식으로 셌습니다**

`substr`·`keyCode` 가 사용 중단으로 잡혔습니다. 그런데 실제로 그 코드가 있는 자리는
`js/aos.js`·`js/lib/iscroll-probe.js`·`js/highlight.pack.js` — 전부 **가져다 쓴 라이브러리**였습니다.
수업에서 가르친 것이 아니라 그 라이브러리의 사정입니다. 이것을 "고쳐야 함"으로 세면
고칠 수 없는 것을 고치라고 말하게 됩니다.

이름과 자리(`lib/`·`.pack.js`·`.bundle.js`)로 거르고, 이름이 멀쩡해도 **줄이 500자를 넘으면
기계가 압축해 낸 코드**로 봅니다. 사람이 손으로 쓴 코드에는 그렇게 긴 줄이 없습니다.

**2. 걸린 파일이 아니라 zip 의 앞 세 파일을 적었습니다**

`substr` 이 `js/aos.js` 에서 걸렸는데 화면에는 `css/main.css` 가 나왔습니다.
사람이 열어 봐도 아무것도 없는 자리였습니다. 실제로 걸린 파일만 적도록 고쳤습니다.

**3. 소제목 아래의 표시를 페이지 전체의 상태로 끌어올렸습니다**

`react.dev` 의 `Component` 페이지 아래쪽 `### componentWillMount` 절에 `<Deprecated>` 가 있습니다.
**그 절 하나가 옛것이라는 말**인데 `Component` 자체가 사용 중단으로 잡혔고,
클래스형 컴포넌트를 가르친 수업자료가 "당장 고쳐야 함"이 되었습니다.

문서가 자기 자신을 두고 하는 말은 언제나 머리말에 옵니다. 그래서 **첫 소제목(`##`) 앞까지만** 봅니다.
13단계에서 `<table>` 의 `### Deprecated attributes` 를 걸러낸 것과 같은 규칙입니다.

#### 화면에서 보기

- **`/compare`** — 상태 필터에 더해 **급한 정도**(고쳐야 함 · 챙겨볼 것 · 알아만 두기)로 좁혀 볼 수 있습니다
- 항목마다 변화 종류와 그 뜻, **예전 방식 → 지금 방식**, 공식 문서가 적어 준 대안을 보여 줍니다
  (모두 공식 문서가 말한 것만 옮깁니다. 지어낸 권장안은 없습니다)
- **자료 상세 `/m/[docId]`** — 급한 것부터 보여 줍니다

#### 테스트

```bash
npm test        # node --test — 18건
```

대부분이 "무엇을 찾아냈는가"가 아니라 **"무엇을 함부로 단정하지 않았는가"** 를 봅니다.
본문의 `removed`·`no longer`, `### Deprecated attributes`, 소제목 아래의 `<Deprecated>`,
메이저 버전 차이 — 전부 확정하지 않아야 통과합니다.

#### refresh 와의 관계

- **dry-run 은 공식 문서를 찾아보지 않습니다.** 찾아보면 `data/doc-lookup.json` 이 새로 쓰이는데,
  그러면 "바꾸지 않겠다"고 말해 놓고 바꾸는 것이 됩니다
- 한 번 찾아본 이름은 `data/doc-lookup.json` 에 남아 다시 요청하지 않습니다
- 비교 항목마다 **공식 문서를 어디서 가져왔는지**(`reference` / `lookup`)를 적어 둡니다.
  이것이 없을 때는 14단계가 찾아낸 문서를 6단계 요약 목록에서 뒤지느라
  아무것도 바뀌지 않았는데도 갱신할 때마다 30건씩 다시 견주었습니다

> **알려진 한계 (14단계 기준)**
> - `RECOMMENDED_CHANGED`·`API_CHANGED` 는 **공식 대응표에 적어 둔 것만** 찾아냅니다.
>   표에 없는 변화는 알지 못합니다
> - 남은 `NOT_FOUND` 20건은 MDN 밖의 것이라 이 방식으로는 영원히 찾지 못합니다
> - 게시형 Google 문서 1건(`github 사용법-desktop_v2`)은 Google 이 요청마다 다른 토큰이 든
>   URL 을 돌려주어 내용 지문이 늘 달라집니다. 그래서 `refresh` 를 돌릴 때마다
>   다시 저장되고 다시 분류됩니다 (`[4/9] 1건을 과목 폴더로 옮겼습니다`).
>   **13단계 이전부터 있던 동작이고 자료가 망가지지는 않습니다.**
>   고치려면 지문을 낼 때 Google 의 임시 토큰(`ust=`·`usg=`·`docs-images-rt`)을 지워야 합니다
>   (18단계 안정화 후보)

### 15단계 실행 결과

14단계까지는 **판정**이었습니다. 15단계는 그 판정을 **다시 공부할 거리**로 옮깁니다.

#### 14단계와 무엇이 다른가

| | 14단계 (`/compare`) | 15단계 (`/study`) |
|---|---|---|
| 답하는 질문 | "이게 지금도 맞나?" | "그래서 어디부터 다시 봐야 하나?" |
| 다루는 것 | 상태·변화 종류·근거 | 그 판정을 옮긴 **설명** |
| 새 사실 | 공식 문서에서 찾아냄 | **하나도 만들지 않음** |
| 단위 | 기술 하나 | 기술 하나 + **수업자료 하나** |

15단계는 **아무것도 새로 판정하지 않습니다.** `changeType`·`severity`·`oldPattern`·
`currentPattern`·`recommendedAlternative`·`evidence` 는 전부 14단계 것을 그대로 받아 씁니다.

#### 복습 우선순위

`changeType` 을 공부하는 사람의 말로 바꾼 것입니다. 판정 기준은
`src/study/study-builder.ts` 의 `priorityOf` 한곳에만 적혀 있습니다.

| 우선순위 | 뜻 | 어떤 changeType 이 오는가 | 현재 |
|---|---|---|---|
| **KEEP** 그대로 복습 | 공식 문서가 아무 경고도 달지 않음 | `NONE` | 307건 |
| **CHECK** 확인하면서 복습 | 개념은 쓸 수 있지만 버전 차이나 확인 못 한 것이 있음 | `VERSION_ONLY` · `REVIEW_REQUIRED` | 44건 |
| **RELEARN** 다시 공부 | 사용법이나 권장 방식이 달라짐 | `API_CHANGED` · `RECOMMENDED_CHANGED` | 0건 |
| **REPLACE** 새 방식으로 교체 | 쓰지 말라고 했거나 없어졌다고 밝힘 | `DEPRECATED` · `REMOVED` | 3건 |

**`VERSION_ONLY` 가 `CHECK` 인 것이 이 표의 핵심입니다.**
버전이 다르다는 이유로 `RELEARN` 에 넣으면, 멀쩡한 수업자료 24건이
"다시 공부해야 할 것" 이 됩니다. 그것은 사실이 아닙니다.

수업자료 하나의 우선순위는 **그 안에서 가장 급한 것**을 따릅니다.
사용 중단이 하나라도 있으면 그 자료는 `REPLACE` 입니다 — 나머지가 멀쩡해도요.

#### 설명 구조

설명 하나는 일곱 칸으로 되어 있습니다. **근거가 없는 칸은 아예 비웁니다.**

```
1. 수업에서 배운 내용   ← 강사 자료의 실제 줄 · 실습파일의 실제 자리
2. 현재 상태           ← 공식 문서의 status · package.json 의 버전
3. 무엇이 달라졌는가     ← changeType
4. 수업 당시 코드/방식   ← oldPattern · 자료에 있던 줄
5. 현재 방식           ← currentPattern · 공식 문서가 적어 둔 대안
6. 지금 다시 공부할 때    ← changeType 별 안내
7. 직접 확인할 근거      ← 14단계 evidence 를 그대로
```

빈 칸에 "없음" 이라고 적지 않습니다. 확인해 본 결과 없는 것처럼 보이기 때문입니다.

#### 지어내지 않기 위해 한 일

**설명에 들어가는 구체적인 값은 전부 비교 결과에서 꺼내 옵니다.**
우리가 아는 일반 지식은 넣지 않습니다 — "React 19 부터 `use` 훅이 생겼습니다" 같은 말은,
그 사실이 맞더라도 우리 자료에 근거가 없으므로 적지 않습니다.

말투도 갈래마다 정해 두었습니다.

| 갈래 | 이렇게 씁니다 | 이렇게 쓰지 않습니다 |
|---|---|---|
| `NONE` | "달라진 점이 확인되지 않았습니다" | "안전합니다" · "앞으로도 괜찮습니다" |
| `VERSION_ONLY` | "사용법이 달라졌다는 근거는 찾지 못했습니다" | "낡았습니다" · "못 씁니다" |
| `NOT_FOUND` | "없어졌다는 뜻이 아니라, 확인하지 못했다는 뜻입니다" | "삭제되었습니다" · "제거되었습니다" |
| `DEPRECATED` | "공식 문서가 더 이상 쓰지 말라고 밝혔습니다" | (여기서는 분명히 말합니다) |

대안이 없으면 **없다고 적습니다** — "공식 문서가 무엇으로 대신하라고 적어 두지는 않았습니다".

걸러 내는 것도 있습니다.

- **목차 링크가 든 줄**은 "수업 당시 코드" 로 내밀지 않습니다
  (`| [align-items](#bookmark=id.d70m…) |` 는 읽어도 아무 내용이 없습니다)
- **데이터 파일(`.json`·`.md`·`.txt`)에 든 낱말**도 코드로 내밀지 않습니다
  (`useNavigate` 가 `public/data/blog.json` 의 `"title"` 값에서 걸린 적이 있습니다).
  근거 목록에는 그대로 남겨 둡니다 — 지우지는 않습니다

#### 외부 AI 를 쓰지 않습니다

설명은 **규칙 기반 template** 으로만 만듭니다. 값만 끼워 넣습니다.

이 프로그램은 나중에 Claude Code 없이도 기본 기능이 돌아가야 합니다.
그래서 유료 AI API 를 필수 의존성으로 두지 않았습니다.
`package.json` 에 늘어난 의존성은 **하나도 없습니다.**

말맛은 덜하지만 **틀린 말을 지어낼 자리가 없다**는 것이 더 중요합니다.
나중에 AI 설명을 얹고 싶으면 `StudyGuide.aiExplanation` 칸이 비어 있습니다.
기본 생성은 그 칸을 절대 채우지 않고, 화면도 없는 것을 정상으로 봅니다.

#### 실행

```bash
node src/index.ts study            # 비교 결과가 바뀌었을 때만 다시 만듭니다
node src/index.ts study --force    # 설명 말투를 고쳤을 때
node src/index.ts study --dry-run  # 결과만 보고 파일은 그대로
```

결과는 `data/study-guides.json` 에 저장됩니다. `comparisons.json` 은 건드리지 않습니다
— 이미 1.2MB 인데 설명까지 넣으면 두 배가 되고, 둘은 바뀌는 때도 다릅니다
(판정은 공식 문서가 바뀔 때, 설명은 말투를 고칠 때).

#### 화면에서 보기

- **`/study`** — 복습 필터(전체 · 그대로 복습 · 확인하면서 복습 · 다시 공부 · 새 방식으로 교체)
  와 과목 필터. 둘은 함께 걸 수 있습니다
- **먼저 볼 자료** — 손볼 것이 있는 자료만 모아 보여 줍니다.
  `KEEP` 인 자료는 여기 넣지 않습니다 — 온통 빨간 화면을 만들지 않기 위해서입니다
- **자료 상세 `/m/[docId]`** — "이 자료 그냥 다시 공부해도 되나" 구역.
  손볼 것이 있을 때만 나옵니다
- **과목 `/s/[subject]`** — 그 과목의 복습 상태 한 줄
- **홈** — "먼저 볼 자료 N건" 카드

각 카드는 **수업 당시 ↔ 현재 방식**을 나란히 보여 줍니다.
코드는 확보된 것을 그대로 씁니다. 고치거나 만들어내지 않습니다.

#### refresh 와의 관계

`npm run refresh` 의 **10번째 단계**로 들어갔습니다.

```
[10/10] 학습 설명 만들기
→ 완료: 견준 결과가 그대로라 다시 만들지 않았습니다 (354건)
```

설명은 비교 결과에서만 나옵니다. 그러니 **비교가 그대로면 설명도 그대로입니다.**
`study-guides.json` 에 적어 둔 `comparisonsGeneratedAt` 이 `comparisons.json` 의
`generatedAt` 과 같으면 만들지 않고 넘어갑니다.

dry-run 은 아무 파일도 쓰지 않습니다.

> **알려진 한계 (15단계 기준)**
> - 설명은 **template 입니다.** 항목마다 문장 구조가 같습니다. 읽기 좋게 다듬은 산문이 아닙니다
> - `RELEARN` 이 현재 0건입니다. 14단계 대응표에 있는 예전 방식이 수업 코드에
>   하나도 없기 때문입니다 (**수업자료가 이미 최신이라는 뜻**이지 판정이 실패한 것이 아닙니다).
>   그래서 그 갈래의 설명은 실제 데이터로는 아직 확인해 보지 못했고, 테스트로만 확인했습니다
> - 비교 항목 354건 중 78건은 어느 수업자료와도 이어지지 않습니다
>   (실습 zip 에만 있고 강사 설명자료에는 없는 것들). `/study` 목록에는 나오지만
>   "먼저 볼 자료" 에는 나오지 않습니다
> - "수업에서 배운 내용" 은 **그 낱말이 나온 줄**입니다. 강사님이 그 주제를
>   어떻게 설명했는지를 요약한 것이 아닙니다

### 16단계 실행 결과

새 기능을 붙인 단계가 아닙니다. **거짓 성공을 없앤 단계**입니다.

#### 무엇이 잘못돼 있었나

15단계 회귀 검증 중에 이런 일이 있었습니다.

```
▸ MDN CSS 속성 (css)
  공식 문서 0개 → 매칭 0개 → 요약 0개
...
  ✓ [6/10] 공식 문서 최신화                    완료
```

GitHub 요청 한도(인증 없이 시간당 60회)를 다 써서 403 이 왔는데,
목록을 받는 코드가 그것을 **빈 목록**으로 바꿔 돌려줬습니다.
그래서 "문서 0개" 가 되었고, 화면에는 `✓ 완료` 라고 찍혔습니다.

**받지 못한 것과 없는 것은 다릅니다.** 이것을 구분하지 못하면 실패가 성공처럼 보입니다.

파고들어 보니 같은 결함이 세 군데 있었습니다.

| # | 어디서 | 무슨 일이 |
|---|---|---|
| 1 | `index-fetcher.ts` | 403·500·타임아웃을 전부 `[]` 로 삼키고 `ok: true` 를 돌려줌 |
| 2 | `enrich-runner.ts` | 0건이어도 `INDEX.md` 를 **빈 목록으로 덮어씀** (실제로 `문서 수: 0개` 가 남았습니다) |
| 3 | `doc-lookup.ts` | 403 을 "그 자리에 없다" 로 보고 `found: false` 를 **캐시에 굳힘**. 한 번 굳으면 다음 실행이 건너뛰어 영영 못 찾음 |

#### 수집 상태 — 네 가지를 구분합니다

| 상태 | 뜻 | 기호 |
|---|---|---|
| `SUCCESS` **최신** | 공식 문서를 정상으로 받아왔습니다 | ✓ |
| `PARTIAL` **일부만 갱신** | 일부 출처는 받아왔고 일부는 못 받았습니다 | ⚠ |
| `STALE` **예전 자료 사용** | 새로 못 받아 이미 가진 것을 그대로 씁니다. **자료를 잃지는 않았습니다** | ⚠ |
| `FAILED` **실패** | 받지도 못했고 쓸 수 있는 예전 자료도 없습니다 | ✗ |

`STALE` 과 `FAILED` 를 가르는 것은 **이미 가진 요약본이 있는가** 하나입니다.
못 받아왔더라도 예전 자료가 있으면 공부는 계속할 수 있으니까요.

**"0건이면 실패" 라고 못 박지 않았습니다.** 문서가 실제로 0개인 출처가 있어서,
그렇게 하면 그것이 새 오탐이 됩니다. 상태는 **요청이 어떻게 됐는지**에서 나옵니다.

기록은 `data/collect-status.json` 에 남습니다. 공식 문서 요약본 자체는 건드리지 않습니다.

#### 요청 한도를 알아내는 방법

문구 하나에 기대지 않습니다. GitHub 은 여러 신호를 함께 주므로 **믿을 만한 순서**로 봅니다.

```
1. x-ratelimit-remaining: 0    ← 기계가 읽으라고 만든 칸
2. retry-after 가 붙은 429/403  ← 짧은 시간에 많이 보냈을 때(2차 한도)
3. 본문의 "rate limit" 문구      ← 마지막 보루
```

`x-ratelimit-reset` 이 있으면 **언제 다시 할 수 있는지**까지 알려 줍니다.

```
⚠ [6/10] 공식 문서 최신화                  이전 데이터 사용
     GitHub API 요청 한도를 넘겨 새로 가져오지 못했습니다.
     약 14분 뒤(10:56 UTC)에 다시 실행할 수 있습니다.
     기존 공식 문서는 그대로 두었습니다 (못 받은 과목: css, html, javascript, typescript, mui)
```

모르면 지어내지 않습니다 — reset 시각을 알 수 없으면 "잠시 뒤에 다시 실행해 보세요" 라고만 적습니다.

#### 기존 데이터를 지키는 방법

원칙 하나입니다.

> **받아오지 못했으면 예전 것을 그대로 둔다.**

- 목록을 못 받으면 `INDEX.md` 를 **아예 건드리지 않습니다** (예전에는 빈 목록으로 덮어썼습니다)
- 받아온 것이 있을 때만, 그것도 **임시 파일에 다 쓴 뒤 이름을 바꿔** 넣습니다.
  쓰는 도중에 멈춰도 파일은 언제나 예전 것 아니면 새것이지, 반쯤 쓰인 것이 되지 않습니다
- 요청 한도에 걸린 문서 찾기는 **"못 찾음" 이라고 적지 않고** 그냥 물러납니다.
  모른다고 적는 것과 아무 말도 하지 않는 것은 다릅니다

실제 데이터로 재현해 확인했습니다 — 요청 한도 상황을 흉내 내 `enrich` 를 돌렸을 때
**공식 문서 209개 중 내용이 바뀐 파일 0개**였습니다.

#### GITHUB_TOKEN 은 선택 사항입니다

**없어도 프로그램은 그대로 동작합니다.** 지금까지와 똑같이 인증 없이 요청합니다.

토큰을 넣으면 요청 한도가 시간당 **60회 → 5,000회** 로 늘어납니다.
공개 저장소만 읽으므로 **권한(scope)은 하나도 필요 없습니다.**

```powershell
# PowerShell — 그때그때
$env:GITHUB_TOKEN = "..."
npm run refresh
```

```bash
# bash — 그때그때
GITHUB_TOKEN=... npm run refresh

# 또는 .env.example 을 .env 로 복사한 뒤
node --env-file=.env src/index.ts refresh
```

`GH_TOKEN` 도 받습니다 (gh CLI 를 이미 쓰고 있다면 그 값이 쓰입니다).

토큰 값은 **어디에도 남지 않습니다** — 로그에도, `collect-status.json` 에도.
저장되는 것은 "썼는지 안 썼는지" 뿐입니다. 자동 테스트로 확인합니다.

#### refresh 출력 읽는 법

```
✓  성공                   실제로 새로 만들거나 갱신했습니다
○  건너뜀 / 변경 없음       할 일이 없었습니다
⚠  이전 데이터 사용         바깥에서 못 받아와 기존 자료를 그대로 씁니다
✗  실패                   이 단계가 실패했습니다
```

`⚠` 는 경고로 찍힙니다. 조용히 지나가면 성공처럼 보이기 때문입니다.

맨 아래에 공식 문서가 얼마나 최신인지 한 묶음이 나옵니다.

```
▸ 공식 문서 최신 상태
  ✓ 최신 — 공식 문서를 정상으로 받아왔습니다.
  마지막 시도 2026-08-23 10:47
  마지막 성공 2026-08-23 10:47
```

**마지막 성공은 실패해도 지워지지 않습니다.** 그래야 지금 보는 자료가
얼마나 오래된 것인지 알 수 있습니다.

#### 실패한 뒤 다시 하려면

게다가 그것을 저장하면 멀쩡하던 예전 비교 결과를 덮어씁니다.

실제로 확인했습니다 — 공식 문서를 치우고 `compare` 를 돌리면 이렇게 멈춥니다.

### 17단계 실행 결과

16단계는 **목록(index)** 을 못 받는 것까지 다뤘습니다.
17단계는 그 뒤 — **문서 원문(content)** 을 받는 데까지 같은 잣대를 들이댑니다.
그리고 잠깐 흔들린 것 때문에 `refresh` 를 처음부터 다시 돌리지 않아도 되게 만듭니다.

#### 목록과 원문은 다른 단계입니다

```
목록(index)   "이 과목에 어떤 공식 문서가 있나"   ← GitHub 디렉터리 · llms.txt   요청 한두 번
원문(content) "그 문서의 내용은 무엇인가"        ← raw 파일 하나하나        요청 수십 번
```

16단계까지 원문 실패는 `failed: 5` 하나로만 셌습니다.
그래서 **무엇이 왜 안 됐는지 알 수 없었습니다** — 다시 해 볼 만한 것인지조차요.

#### 실패 유형

| 유형 | 뜻 | 다시 하나 |
|---|---|---|
| `RATE_LIMIT` | 서버가 요청 한도를 넘겼다고 **직접 밝힘** | ○ (기다릴 만하면) |
| `TIMEOUT` | 정해진 시간 안에 응답 없음 | ○ |
| `NETWORK` | 아예 닿지 못함 (DNS·연결 끊김) | ○ |
| `HTTP_ERROR` | 응답은 왔는데 오류 | 429·5xx 만 ○ |
| `NOT_FOUND` | 그 자리에 없음 (404) | ✗ |
| `PARSE_ERROR` | 받긴 받았는데 읽어내지 못함 | ✗ |
| `UNKNOWN` | 위 어디에도 안 맞음 | ✗ |

**`NOT_FOUND` 는 실패가 아닙니다.** 16단계에서 정한 것과 같은 이유입니다 —
다시 해도 없고, 예전 자료가 낡은 것도 아닙니다.
그래서 세어서 알리되 **상태를 `PARTIAL` 로 내리지 않습니다.**
그렇게 하면 고칠 수 없는 경고를 영원히 띄우게 됩니다.

#### 자동 재시도

**처음 1번 + 다시 2번, 모두 3번이 끝입니다.** 무한 재시도는 없습니다.

쉬는 시간은 조금씩 길어집니다 — `500ms` → `1,500ms`.
곧바로 다시 두드리면 서버 쪽 사정이 나아질 틈을 주지 않기 때문입니다.
서버가 `retry-after` 로 알려 주면 그 말을 따르되, 그것도 상한을 넘으면 듣지 않습니다.

#### 요청 한도 자동 대기

`x-ratelimit-reset` 으로 **언제 풀리는지 알 수 있고**, 그게 **짧으면** 기다렸다 이어갑니다.

```
[알림] 요청 한도에 닿았습니다. 약 1분 30초 뒤에 다시 시도합니다. 기존 자료는 그대로 있습니다.
[알림] 요청 한도가 풀렸습니다. 멈췄던 자리에서 이어갑니다.
```

**상한은 5분입니다.** 그보다 오래 남았으면 기다리지 않습니다.

```
[알림] 요청 한도가 풀리기까지 44분 59초 남았습니다.
       자동으로 기다리는 상한(5분)을 넘어 여기서 멈춥니다.
```

사용자를 45분씩 아무 설명 없이 붙잡아 두는 것은, 실패를 숨기는 것만큼이나 나쁩니다.
상한은 `CMM_MAX_RATE_LIMIT_WAIT_SECONDS` 로 바꿀 수 있습니다. 설정 화면은 만들지 않았습니다.

**언제 풀리는지 모르면 기다리지 않습니다.** 얼마나 걸릴지 말해 줄 수 없으니까요.

#### 이어받기

다시 하기는 **문서 하나 안에서만** 일어납니다.
30번째 문서에서 한도에 걸려 기다렸다 이어가더라도 **1~29번째를 다시 받지 않습니다.**
처음부터 되돌리는 자리가 없기 때문입니다. (자동 테스트로 고정해 두었습니다)

기다릴 수 없는 한도를 만나면 **남은 문서는 손대지 않고 멈춥니다.**
계속 두드려 봐야 같은 답만 오고, 남의 서버만 괴롭히며 우리 한도만 더 씁니다.
손도 못 댄 문서는 **실패와 따로 세어** 사실대로 알립니다.

#### 실패 문서 기록

`data/collect-status.json` 에 남깁니다. **단서만 적습니다** — 응답 본문도 토큰도 담지 않습니다.

```json
{
  "source": "css",
  "id": "grid",
  "failureType": "TIMEOUT",
  "attempts": 3,
  "lastAttemptAt": "2026-08-23T11:14:00.000Z",
  "usingPreviousData": true
}
```

`usingPreviousData` 가 `true` 면 그 자리에 예전 요약본이 남아 있다는 뜻입니다 —
못 받았어도 공부는 계속할 수 있습니다.
기록은 20건까지만 쌓습니다. 목록이 아니라 **무슨 일이 있었는지 알아볼 단서**이기 때문입니다.

#### llms.txt 출처

`react.dev`·`nextjs.org` 는 GitHub 이 아니라 `x-ratelimit-*` 머리말이 없습니다.
그래서 **429 가 왔다는 것만으로 "GitHub 요청 한도" 라고 부르지 않습니다.**
`HTTP_ERROR` 로 두고 상태 코드만 적습니다. 다시 해 볼 만한 실패로는 봅니다.

근거가 없는데 추측해서 이름 붙이지 않는다 — 13단계부터 지켜 온 것과 같은 규칙입니다.

#### 토큰은 GitHub 에만 붙습니다

17단계에서 `llms.txt` 도 같은 길을 지나가게 되었습니다.
그때 토큰을 그대로 붙이면 **남의 서버에 내 GitHub 토큰을 보내는 셈**입니다.
그래서 주소의 **호스트 이름을 정확히 보고** GitHub 일 때만 붙입니다
(`https://evil.test/?x=github.com` 같은 주소에 속지 않습니다).

#### 17단계가 드러낸 것 — 잃고 있던 문서 2건

원문 실패를 유형별로 세기 시작하자마자 이런 것이 나왔습니다.

```
html       | input    | NOT_FOUND 404
javascript | iterator | NOT_FOUND 404
```

찾아보니 MDN 한국어 저장소에는 **폴더는 있는데 `index.md` 가 없는** 경우가 있었습니다.
목록에는 잡히지만 원문을 받으려 하면 404 가 납니다.
**그런데 영어 원문은 멀쩡히 있었습니다.**

한국어를 우선하는 병합 과정에서 영어 주소를 버리고 있었습니다.
이제 영어 주소를 대체 자리로 챙겨 두었다가, **한국어에 본문이 없을 때만** 그것으로 받습니다.
("없음(404)" 일 때만입니다 — 요청 한도나 서버 탈일 때는 다른 자리를 봐도 소용없습니다)

그래서 공식 문서 요약본이 **201건 → 203건**이 되었습니다. 되찾은 것입니다.

## 설계에서 지킨 것들

**중복을 막는 방법** — 링크를 문자열로 비교하지 않고 **ID로 비교**합니다.
같은 문서가 `?tab=`, `#bookmark=`, `google.com/url?q=` 래퍼 등 여러 모습으로 등장해도
`url-normalizer.ts` 를 거치면 하나로 합쳐집니다.
실제로 Google 문서는 243회 등장하지만 고유 자료는 233건이었습니다.

**게시형 URL 함정** — `/document/d/e/2PACX-…/pub` 형태를 순진한 정규식은
문서 ID를 `"e"` 로 잘못 읽습니다. `url-normalizer.ts` 에서 이 패턴을 **가장 먼저** 검사합니다.

**이미지 45MB 문제** — 기준 문서의 HTML은 45.6MB인데 그중 98.8%가 본문에 박힌 base64 이미지입니다.
받자마자 제거해 0.55MB로 줄인 뒤 사용합니다.

**섹션 정보 보존** — 링크가 문서의 어느 섹션 아래에 있었는지 함께 기록합니다.
기준 문서의 섹션 이름이 이미 `React`, `Next.js`, `TypeScript`, `FLEXBOX` 처럼 구체적이라
5단계 과목 분류에서 가장 강한 단서가 됩니다.

**공식 문서와 다를 때** — 수업에서 배운 방식은 삭제하지 않고, 공식 문서의 최신 방식을
나란히 기록한 뒤 차이를 `deprecated` / `still-valid` / `preference` / `version-gap` 으로 표시합니다.

## 주의사항

- `data/` 폴더는 git에 올리지 않습니다. 강사 저작물과 개인정보가 들어 있습니다.
- Google 아이디와 비밀번호는 코드에도 파일에도 저장하지 않습니다.
  2단계 인증은 OAuth 방식으로, 브라우저 동의 화면을 거쳐 받은 토큰만 로컬에 보관합니다.
- Chrome 쿠키를 직접 복호화하는 방식은 사용하지 않습니다.

### 7단계 — 뷰어

수집한 자료를 브라우저에서 읽는 화면입니다. **읽기 전용**입니다.

```bash
cd viewer
npm install
npm run dev     # → http://localhost:3000
```

| 화면 | 내용 |
|---|---|
| 홈 | 전체 규모와 과목 카드 |
| 과목별 목록 | 수업자료와 공식 문서 요약을 나란히 |
| 자료 상세 | 본문 + 원본 링크 + **이 주제의 공식 문서** |
| 검색 | 제목과 **본문까지** 함께 검색 |

원본을 바꿀 수 있는 코드가 아예 없습니다 — 파일을 쓰는 함수도, API 라우트도 만들지 않았습니다.
자세한 내용은 [viewer/README.md](viewer/README.md) 를 보세요.
