# 앞으로 — v1.0.0 이 못 하는 것과 해 볼 만한 것

v1.0.0 은 **계속 쓸 수 있는 상태**로 닫은 것이지, 모든 것을 다 한 상태가 아닙니다.
이 문서는 "지금 안 되는 것"을 숨기지 않고 적어 둔 자리입니다.
다음에 이어서 할 사람(대개 미래의 나)이 처음부터 다시 조사하지 않도록 **이유까지** 남깁니다.

---

## 지금 못 하는 것 (알려진 한계)

### 1. 수업 방식과 공식 문서의 "차이 판정" 은 규칙으로만 합니다

`comparisons.json` 의 판정은 공식 문서의 `status` 값과 패키지 버전만 근거로 삼습니다.
글의 뜻을 읽고 견주는 것이 아닙니다.

- **그래서 생기는 일** — 문장은 다르지만 뜻이 같은 경우를 `CHECK` 로 올려둘 수 있습니다.
  (현재 `KEEP 308 · CHECK 44 · REPLACE 3`)
- **왜 그대로 두었나** — 규칙으로 못 하는 일에 규칙을 더 붙이면 오탐만 늡니다.
  `src/enrich/summarizer.ts` 의 `Summarizer` 인터페이스에 AI 구현을 끼워 넣으면
  이 칸이 자동으로 채워지도록 자리는 이미 비워 두었습니다.

### 2. 공식 문서 요약은 원문 문단을 그대로 뽑습니다

요약이 아니라 **발췌**입니다. 6단계에서 정한 방식이고 v1 에서도 그대로입니다.
사람이 읽기에 충분해서 바꾸지 않았습니다.

### 3. 실행 도중 끊기면 그 명령은 처음부터 다시 합니다

`refresh` 는 아홉 단계를 순서대로 부르는데, 도중에 끊기면 **끊긴 명령**은 다시 처음부터입니다.
다만 이미 받아 둔 자료는 다시 내려받지 않으므로(변경 감지) 실제로 걸리는 시간은 짧습니다.

- **17단계에서 넘어온 검토 항목** 이었고, 18단계에서 **가치 판단 끝에 하지 않기로** 했습니다.
- **이유** — 이어받기 상태를 파일로 남기면 그 파일 자체가 또 하나의 고장 지점이 됩니다.
  지금은 "다시 돌리면 된다" 가 더 단순하고 안전합니다. 실제로 불편해지면 그때 붙이면 됩니다.

### 4. 자료(`data/`) 안에는 민감정보로 보이는 것이 남아 있습니다

`npm run security-check` 는 현재 **7건**을 의심 항목으로 보고합니다
(Google API 키 2 · GitHub 토큰 1 · OAuth 클라이언트 비밀 1 · 자격증명 같은 대입문 3).

- 대부분 **수업자료 원문에 강사가 예제로 적어 둔 것**이고, 하나는 내 `data/token.json` 입니다.
- `data/` 는 `.gitignore` 대상이라 **git 으로는 새어 나가지 않습니다.** 검사도 이 둘을 나눠서 봅니다.
- **원본은 자동으로 고치지 않습니다.** 강사 저작물을 프로그램이 임의로 바꾸지 않는다는 원칙입니다.
- 자료를 다른 곳으로 옮기거나 공유하기 전에는 **사람이 직접** 확인해야 합니다.

### 5. 브라우저 시험은 Chromium 하나로만 돕니다

개인용 도구라 내가 쓰는 브라우저 하나면 충분하다고 보았습니다.
`playwright.config.ts` 의 `projects` 에 줄을 더하면 Firefox·WebKit 도 같이 돕니다.

## 손대기 전에 알아 둘 것

- **`data/` 는 git 에 올리지 않습니다.** 강사 저작물과 개인정보가 들어 있습니다.
  대신 변경 이력은 `data/history/`, 백업은 `data/backups/` 에 직접 보존합니다.
- **줄바꿈은 LF 로 고정**되어 있습니다(`.gitattributes`).
  소스를 글자 그대로 읽어서 검사하는 시험이 있어서, CRLF 로 받아지면 그 시험이 깨집니다.
  18단계 최종 검증에서 실제로 이 문제가 잡혔습니다.
- **원본 수업자료는 프로그램이 고치지 않습니다.** 새로 만드는 파일만 씁니다.
- 무엇을 바꾸든 `npm test` · `npm run e2e` · `npm run security-check` 세 가지는 통과해야 합니다.
